# AI access

Everything that lets an AI read or change the ledger lives here. The MCP server and the built-in assistant share one set of tools, so a capability added once works in Claude Code, Codex, Cursor and the in-app assistant alike.

| File                    | Role                                                                                                                                                                                                                                               |
| ----------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `mcp.ts`                | MCP server at `/mcp`: Streamable HTTP in stateless mode (each POST is one JSON-RPC request, plain JSON response, no SSE or sessions). Bearer tokens are created on the AI access page, stored as SHA-256 only, and scoped read-only or read-write. |
| `mcp-tools.ts`          | Catalogue entry: preserves tool order, applies schema validation, and exposes connection information.                                                                                                                                              |
| `tool-kit.ts`           | Shared types, argument/reference resolution, schema fragments and the single ledger-write pipeline.                                                                                                                                                |
| `tool-views.ts`         | Shared output rows, amounts, collection summaries and previews.                                                                                                                                                                                    |
| `read-tools.ts`         | Read handlers and their schemas.                                                                                                                                                                                                                   |
| `subscription-tools.ts` | Subscription, phase, status, payment and transfer write handlers.                                                                                                                                                                                  |
| `share-tools.ts`        | Shared-plan and receivable handlers.                                                                                                                                                                                                               |
| `report-tools.ts`       | JSON output for the month and list selection reports, and the shared list filter argument.                                                                                                                                                         |
| `ledger-tools.ts`       | Wallet, category, people, proxy and sanitized business-settings handlers; pure rules live in `shared/ledger-edit.ts`.                                                                                                                              |
| `assistant.ts`          | Built-in assistant: streams a DeepSeek-compatible chat, calls the same tools, and turns every write into a draft the user confirms first. Request/response helpers shared with the browser are in `shared/deepseek.ts`.                            |

## Tools

- **Read**: `get_overview`, `list_categories`, `list_subscriptions`, `get_subscription`, `list_charges`, `spending_stats`, `get_trends`, `list_payment_methods`, `list_people`, `get_receivables`, `get_insights`, `list_events`, `get_carpool`, `search_app_store`, `get_settings`.
- **Write**: `create_subscription`, `save_subscription`, `update_subscription`, `change_price`, `change_plan`, `set_status`, `record_payment`, `delete_payment`, `record_transfer`, `delete_subscription`, `set_share`, `save_share_member`, `remove_share_member`, `record_receivable`, `update_payment_method`, `save_category`, `save_person`, `set_proxy`, `update_settings`.

Write tools are hidden from read-only tokens and rejected if called anyway. Read and ordinary edit tools resolve a subscription from its id, exact name or a unique partial name; destructive actions (`delete_subscription`, `delete_payment`, `remove_share_member`, `change_plan action=remove|drop`, `set_share role=none`, `set_proxy action=remove`, `record_receivable action=delete`) accept only an id or the exact full name (case-insensitive) and otherwise return candidates. Shared-plan members resolve by id or a unique exact name (case-insensitive); `record_receivable` (except delete) also accepts a unique partial name, and duplicate names always return candidates. All accept `dry_run: true`, which returns a preview without saving; the assistant always uses it before asking for confirmation. MCP clients with a read-write token write directly unless they pass `dry_run`.

Subscription category assignments resolve exact codes/names first, then case-insensitive stored or localized preset names, and reject missing or ambiguous matches with candidates. Call `list_categories` first; missing categories require `save_category action=create` or explicit `create_category: true` on `create_subscription` / `update_subscription`. Optional top-level `category_icon` / `category_color` use the same validation as `save_category set.icon/color`. A new category and its subscription reference save atomically; previews list `created_category` and a creation notice without writing. Existing matches are reused even with the flag, ambiguity never creates a category, and historical names exposed by `categoryList` remain valid. Omitted create categories default to an existing Tools preset; if it was removed, specify an existing category. The assistant preserves category inputs for this same validation and displays category creation on its confirmation card.

`get_settings` also returns credential-free connection identity, local date/timezone, base currency, actual caller scope and the tools available to that caller; initialization includes the same context. `list_subscriptions` searches/returns login accounts, and ambiguous names include account, region and payment context. Same-name subscriptions with different explicit accounts remain independent.

The catalogue has 34 tools. `save_subscription` writes one complete subscription record (a whole history or an already-stopped record) with the web editor's full-record validation; its preview lists field changes and computed before/after values. `update_payment_method` manages wallet creation, full field edits, deletion with reference migration, balances and indexed top-up revisions. `save_category` and `save_person` manage their registries and migrate references atomically; category order and wallet order are editable. `record_receivable` records, waives, updates and deletes per-period receipts for members and proxy charges (chosen `periods` or the `count` earliest unsettled, possibly skipping owed ones or prepaying), and sets a proxy charge's actual card charge; deleting a record reopens its periods. `set_status` also marks an existing subscription as trial with an optional first paid date. `record_payment` (whose optional `currency` must equal the phase currency for every payment kind; other card currencies go in `settled`) can replace a recorded charge and set or clear a per-charge payment method (`method`; omitted keeps a replaced charge’s own method) or split it across sources (`funding`, exclusive with `method`); `set_status` cancel/terminate require an explicit `at` for subscriptions that began before today (`at: null` = stopped on an unknown date), and with `edit: true` correct an existing stop's date, non-renewal/immediate kind, reason or refund like the web stop fields (provider termination stays terminate), `change_plan` can correct/remove a specific phase, and `update_subscription` covers optional appearance, public visibility, dates and promotions (icons on create and update share one validation and reject invalid values). Read tools expose editable records and stable array indices. Person summaries omit image bytes and include `has_avatar`. `save_share_member` and `set_proxy` link a new name to a matching roster person or create one like the web forms (preview `created_person`; `person: null` keeps it unlinked). `save_person` accepts top-level `avatar_base64` + `mime` (`image/png` / `image/webp`), or `avatar: null` to remove. Supply a metadata-free square thumbnail up to 128×128 and 64 KiB; remote URLs are unsupported. Preview results identify the avatar action and status without echoing the image.

`get_insights section=month_report` (`month=YYYY-MM`, default this month) and `section=scope_report` (`filter`) return the calendar month report and the list selection report from [scope reports](../../ARCHITECTURE.md#scope-reports) as JSON blocks: base-currency amounts at my share, with original bill amounts on charge and transfer rows. Missing FX yields `null` figures, `incomplete`, `fx_missing` and an `unconverted` list instead of zeros. `filter` (status, category, method or `none`, query, plus MCP-only tag, region and subscriptions) uses the web list predicate in `shared/list-scope.ts`; `spending_stats` accepts the same `filter` and an opt-in `include_transfers` (default off: provider charges only, as report composition). Report formatting lives in `report-tools.ts`. Scope reports add `lifecycle` without removing legacy blocks/headline fields: `cumulative_spending`, `average_duration_days`, `active_count`, `stopped_count`, `terminated_count`, `unrefunded_loss`, `termination_loss`, complete `stops` (including full refunds and zero unused days), `timeline`/`timeline_omitted` (up to twelve by cumulative spending, displayed newest start first, then name) and historical charge-source `spending`. Only the phase-eight `lifecycle.saved` savings field has been removed; stop details, losses, historical spending and all legacy blocks remain available despite the trimmed selection UI. Lifecycle totals expose `total: null` and `incomplete`/`fx_missing` when conversion is incomplete, together with `known_total` and `unconverted`; stop rows retain original loss/refund amounts, converted values, used/unused/wasted days and refund status. Selection trends have twelve months through the current month, cash through today, with no forecast months. Calendar `month_report` adds `next_month` (the following month on the same net-cash basis); scope headlines add `this_year_with_forecast`. `section=year_outlook` returns `yearOutlook()`: this year paid/pending/total, `same_period` against last year (with `no_previous` when last year has no cash), up to ten `drivers`, `next_month` and `next_year`. The other read tools follow the same rule: a converted amount that has no usable FX rate is `null` (never 0), and totals that include one are `null` with `incomplete: true` and `fx_missing` currencies — `list_charges` (rows carry `fx_missing: true`), `get_subscription.spent_total`, `save_subscription` preview `computed`, `get_overview`, `list_subscriptions`, `list_people`, `get_receivables`, `get_carpool` (`year` / `to_date` carry `incomplete`) and `list_payment_methods` (`runway.incomplete`). Reminder digests show such amounts as “—”.

`change_price` defaults to adding/upserting a price at `from` (today by default). `action=edit|remove` targets `phase` (its exact start) and `original_from`; edit accepts `amount` and optional new `from`. The initial price is editable but cannot be removed. `change_plan action=edit` also accepts a complete `set.priceHistory` array to revise or remove later points. Its `set.start` (and `update_subscription set.start`) moves a start through the web editor's `movePhaseStart()`, keeping the billing anchor and future charge dates unless `shift_billing: true`. See [billing and historical truth](../../ARCHITECTURE.md#billing-and-historical-truth) for validation, price derivation and estimated-charge behavior. Both tools report `affected_estimated_charges` and preserve preview and write-scope checks.

`get_settings` / `update_settings` expose a field whitelist of business settings, existing notification-channel enable switches and known UI preferences. Their sanitized previews omit credentials. The catalogue schemas are also enforced at runtime for MCP and assistant calls; unknown fields and invalid nested payloads are rejected. Pure reference/migration and settings rules live in `shared/ledger-edit.ts`. Multi-entity changes use one transactional `saveLedgerEdit` batch. Tool state reads skip the legacy auto-person migration so even old-ledger previews cannot write.

The assistant uses the entire same catalogue. Every chat write is forced to `dry_run`; wallet/person/category/settings drafts join the subscription overlay so later calls can reference them. New entity IDs are pinned into confirmation arguments. The apply endpoint re-previews current data, pins generated IDs/defaults (including receipt/waiver IDs), saves, and verifies intended changes by reading persisted data. Its additive `verification` result distinguishes verified from saved-but-unverified results; clients must check the latter instead of blindly retrying. Confirmation cards include before/after data and references; dependent batches stop on failure or uncertainty.

Chat has a 12-round tool budget and one tool-free closing attempt on exhaustion. `done.outcome` reports `complete`, `partial` or `limit` plus unresolved failures and draft count. Failed drafts can retry after dependencies are available. The UI warns on unfinished turns and does not present the model’s final completion claim as authoritative. `save_subscription` publishes its complete known field structure and a gifted/early-renewed/stopped history example from `shared/subscription-schema.ts`; known fields are validated, while legacy extensions remain accepted.

Tool results longer than 24,000 characters reach the model as valid JSON `{truncated, original_chars, note, partial}` rather than a cut-off object. Each stored conversation is limited to 1,800,000 UTF-8 bytes (the roster budget, below D1's 2 MB row limit). Every model round rebuilds the system prompt from a fresh ledger read; this is intentional and not cached.

**Deliberately unavailable:** authentication, passwords, Passkeys, sessions and session limits; MCP tokens and the AI access switch; private ICS tokens; AI provider configuration/keys; backups, restore, import/export, reset/migration and whole-ledger deletion; outbound notification channel addresses, configuration and secrets. Channel setup remains in the web UI; tools can only toggle an existing channel. FX fetching/backfill, notification sends/tests and chat archive management are operational/integration actions outside ledger editing. Private/public request paths and `maskForPublic` remain unchanged.

`get_insights section=year_review` reports net cash at my share, including refunds and transfer cash; `charges` counts service debits only (no refunds or failed charges). Annual new/ended/longest lists exclude proxy subscriptions. Missing FX produces null amounts. This uses the same shared `yearReview()` as the web annual review.

## Adding or changing a tool

1. Define it in the owning `read-tools.ts`, `subscription-tools.ts`, `share-tools.ts` or `ledger-tools.ts` module, then place it in the original order in `mcp-tools.ts`: a clear English description (it is the model's only documentation), a strict schema, `write`/`destructive`/`idempotent` flags, and a `dry_run` preview for writes.
2. Validate inputs with the shared helpers and throw errors with `t('mcp.error.*')`. Add new error keys to all 14 locales in `shared/locales/<lang>/mcp.json`.
3. Reuse domain logic from `shared/` (billing, phases, carpool, metrics) instead of re-implementing it, so the app, the MCP server and the assistant agree.
4. Add tests under `shared/*.test.ts`, run `npm run i18n:check` and `npm test`, and keep this catalogue summary and the architecture boundary current. The connection page reads `/api/mcp/tools` dynamically; add localized `mcp.tool.<name>` titles rather than maintaining a duplicate list.

### Partial currency totals

Read amounts keep existing nullable converted totals, `incomplete` and `fx_missing` semantics. Additive `known_total` is the known portion in the response currency; `unconverted` is a currency-to-signed-original-amount map. It includes refunds and transfer direction and uses actual card settlement amounts when recorded; projections use current rates, historical cash uses its date. `get_overview` uses monthly my-share spend; charge/subscription/receivable/statistics tools use their documented scope. Trend points and report blocks expose the same fields; per-measure `totals` distinguish cash/accrual, paid/pending and other measures. Existing report-root `unconverted` **row arrays remain compatible**: their aggregate map lives in `totals.unconverted`, with `known_total` also at the root. All-missing totals have `known_total: 0`; clients must inspect `incomplete` and `unconverted` before presenting zero or calculating ratios. Browser presentation is owned by `shared/fx-total.ts` as described in [Architecture](../../ARCHITECTURE.md#billing-and-historical-truth).

Transfer labels use Bought / Sold (买入 / 卖出 in Simplified Chinese) across the detail card, editor, history and assistant proposal. MCP `record_transfer.kind` and read/report JSON retain the machine values `buy` / `sell`; amount signs and transfer accounting are unchanged.
